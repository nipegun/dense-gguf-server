Dense GGUF Server — независимый проект, который разрабатывает и поддерживает **NiPeGun**.

DGS обслуживает следующие плотные модели и связанную с ними веб-программу для чата:

- Qwen3.8-27B
- Qwen3.5-9B
- Qwen3.5-4B
- Qwen3.5-2B

Другие языковые модели, включая все версии GLM и Kimi, не поддерживаются. Модели MoE по-прежнему исключены. Сервер проверяет исходную идентичность GGUF и размеры слоёв, в том числе при загрузке черновой модели для спекулятивного декодирования. Квантования разрешённых моделей поддерживаются.

## Сборка и запуск в Debian

Используйте Debian 13 или совместимую систему с C++17, CMake 3.19+, Python 3.13+ и Node.js 20.19+ либо 22.12+. Установите пакеты от имени root:

```sh
apt-get update
apt-get install -y build-essential cmake ninja-build pkg-config libssl-dev python3 nodejs npm
cmake -S build -B _/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build _/build --target dgs-server -j 8
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. Веса предоставляются отдельно. Для изображений и видео укажите соответствующий проектор Qwen через `--mmproj`; обработка видео также использует FFmpeg. Аудиомодели и генерация аудио не поддерживаются.

По умолчанию включены Release, нативные ядра CPU и поддерживаемая оптимизация при компоновке. Для CUDA и Vulkan используйте `-DGGML_CUDA=ON` или `-DGGML_VULKAN=ON` с нужным SDK. Собирайте для CPU целевой машины либо укажите `-DGGML_NATIVE=OFF`. Увеличение пропускной способности не измерялось.

## Только актуальные форматы

Принимается только GGUF v3. `general.name` либо сочетание `general.basename` и `general.size_label` должно идентифицировать разрешённую модель; одного имени файла недостаточно. Это проверка метаданных и размерностей, а не подлинности весов. Файл Qwen3.5-27B не принимается как Qwen3.8-27B лишь потому, что размерности архитектур совпадают.

Чату нужен полный Jinja-шаблон модели или `--chat-template-file`. Старый движок фиксированных шаблонов, переключатель `--jinja`/`--no-jinja`, устаревшие C API, старые варианты длинных параметров CLI и прежний режим рассуждения удалены. Сохраняются актуальные контракты `/api/v1/*`; старые псевдонимы `/completion` и `/embedding` удалены.

Веб-интерфейс использует актуальное пространство хранения `DgsUi` и структурированные сообщения. Старые пространства, темы, маркеры сообщений и прежние JSON-экспорты диалогов не читаются и не мигрируются. Поддерживаются актуальные сеансы JSONL и архивы ZIP. Старые данные браузера не удаляются. MCP использует StreamableHTTP или WebSocket; прежний транспорт SSE и автоматический переход на него убраны. Буферу обмена нужна актуальная Clipboard API в безопасном контексте.

## Структура и документация

- `backend/`: сервер, инференс Qwen, общие тензорные ядра и компьютерное зрение Qwen.
- `frontend/`: текущая программа Svelte и закреплённые версии зависимостей.
- `deploy/`: средства сборки и встраивания локального веб-интерфейса.
- [Техническая карта](CODE.ru-RU.md) и [руководство](MANUAL.ru-RU.md).

Обычная сборка компилирует и встраивает локальный интерфейс. Для повторного использования интерфейса, уже собранного командой `cd frontend && npm ci && npm run build`, задайте `-DDGS_USE_LOCAL_UI=ON`. После изменения исходников пересобирайте ресурсы. `-DDGS_BUILD_UI=OFF` исключает встроенные ресурсы; в этом режиме укажите `--path` с каталогом актуального собранного интерфейса.

Правила проекта запрещают тесты. Проверка ограничена компиляцией и статическим анализом типов; инференс и бенчмарки не выполнялись. Git в проекте не используется. Защищённый каталог `.git` удаляет его владелец вручную.

## Повседневная работа

Начните диалог, выберите загруженную разрешённую модель и отправьте текст или поддерживаемые изображения/видео. Настройки управляют сэмплингом, контекстом и инструментами. `-c` задаёт длину контекста, `-t` — потоки CPU, `-ngl auto` — автоматическое размещение на GPU. Для аутентификации используйте `--api-key`. Совместимые клиенты подключаются к `http://127.0.0.1:8080/api/v1` и `/api/v1/chat/completions`. В каталогах могут быть другие файлы, но загрузчик отвергает неподдерживаемые контрольные точки.

При ошибке загрузки проверьте идентичность, архитектуру, размерности и версию GGUF; не меняйте метки другой модели ради обхода проверки. При нехватке памяти уменьшите контекст, размер пакетов или объём переноса на GPU. Если интерфейс отсутствует, пересоберите его либо задайте `--path`.

## MCP и функции веб-интерфейса

Включите встроенный MCP-сервер оболочек через `--local-shell-mcp-server` или `DGS_ARG_LOCAL_SHELL_MCP_SERVER=1`. Интерфейс автоматически обнаруживает его и запрашивает разрешение на вызовы инструментов. Доступны установленные Bash, Zsh, sh и PowerShell; показываются команда, stdout и stderr, а каждый вызов записывается в JSONL.

Интерфейс включает монитор CPU/GPU и памяти, строку состояния, общие настройки на сервере, выбор из 15 языков, необязательную инструкцию отвечать на выбранном региональном языке и уведомления об очереди, различающие веб-запросы и другие API-клиенты. Сохраняются просмотр и загрузка моделей, вкладки диалогов и политика плотных моделей.

Интерфейс доступен по `/`; API по умолчанию размещён под `/api`. OpenAI-совместимые клиенты должны использовать базовый путь `/api/v1`. Swagger доступен по `/api/doc/`. У новых API-путей нет псевдонимов в корне. `--api-prefix` выбирает путь под `/api`; `/api/config.js` сообщает его интерфейсу.

## MCP локальных оболочек

```sh
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --local-shell-mcp-server --api-key YOUR_KEY
```

Откройте интерфейс и введите API-ключ. Запись `local shell mcp server` появляется автоматически, когда функция включена на сервере; её можно отключить глобально или для диалога. Инструменты `bash.run`, `zsh.run`, `sh.run` и `psh.run` доступны только для установленных интерпретаторов. Конечная точка — `POST /api/mcp/shell`, транспорт MCP Streamable HTTP, ответы JSON, версия протокола `2025-11-25`.

Каждый инструмент принимает `command`, необязательный `cwd` и необязательный `timeout` в секундах: по умолчанию 60, максимум 3600. Вызовы запускаются в отдельных процессах без интерактивного терминала. Изменения рабочего каталога и окружения не сохраняются между вызовами. Отмена или тайм-аут завершает группу процессов. Команды получают права учётной записи сервера; защищайте доступ API-ключом.

Чат отдельно показывает stdin (команду), stdout и stderr с кодом завершения. Настройки отображения позволяют автоматически раскрывать блоки. Журналы в `~/.dgs/local-shell-mcp-server/` содержат полную команду и вывод: по одному JSONL с отметкой времени на вызов. Длинный вывод в чате может сокращаться. Файлы доступны только серверной учётной записи и автоматически не ротируются.

В Linux с уже установленным sudo запрос пароля появляется в диалоге с активным полем ввода и кнопками принятия/отмены. Пароль передаётся только вспомогательному процессу, не модели, диалогу чата или журналам. Ожидание пользователя приостанавливает отсчёт времени команды; неотвеченный запрос истекает через пять минут. Проект не устанавливает sudo и не требует его для промышленной эксплуатации.

## Мониторинг и общие настройки

Откройте **Мониторинг** в боковой панели или нажмите нижнюю строку состояния. Загрузка CPU/GPU обновляется каждые две секунды при видимой странице. Полный экран дополнительно показывает RAM, VRAM, температуру и потребление, если драйвер предоставляет эти данные. Память разделена на плотные веса, веса MTP/черновика, KV/рекуррентные кэши, вычислительные буферы, сохранённые промпты/контрольные точки, прочее использование и свободную память. NVIDIA опрашивается динамически через NVML, AMD — через sysfs; недоступные значения остаются неизвестными. Режим маршрутизатора агрегирует загруженные дочерние процессы, не загружая и не пробуждая модели.

Настройки хранятся в `~/.dgs/config/ui-settings.json` серверной учётной записи с режимом 0600. Браузеры одного сервера разделяют конфигурацию, тему, язык, избранное и предпочтения инструментов. Сохранение заменяет весь документ; при одновременных изменениях действует последнее успешное сохранение. API-ключи остаются в браузере, как и диалоги, временная навигация и состояние потоков. Старые настройки не мигрируются.

Выберите язык в общих настройках. Изменение сохраняет выбор и перезагружает интерфейс; сначала сохраните другие незавершённые изменения. Поддерживаются локали `de-DE`, `en-GB`, `en-US`, `es-AR`, `es-ES`, `fr-FR`, `he-IL`, `hi-IN`, `it-IT`, `ja-JP`, `ko-KR`, `pt-BR`, `pt-PT`, `ru-RU`, `zh-CN`. Американский английский — язык по умолчанию и замена для непереведённых строк. Включите **Отвечать на языке интерфейса** (Respond in the interface language), чтобы добавлять региональную инструкцию к новым запросам, циклам инструментов, заголовкам и предварительному заполнению KV. Старые сообщения не переводятся; соблюдение инструкции зависит от модели.

Пока запрос ждёт свободный слот, отображается число запросов перед ним и наличие среди них прямых API-запросов. Обычные API-клиенты сохраняют привычный формат ответа. Только потоковые запросы с меткой `"dgs_client": "webui"` получают события `dgs_queue`.

При разработке frontend команда `npm run dev` проксирует `/api` на `http://localhost:9931`; для другого сервера задайте `VITE_PUBLIC_SERVER_ORIGIN`. Промышленная сборка встраивает интерфейс и локальный Swagger без внешней CDN документации.

## Каталоги исходников и сборки

`build/` содержит точку входа CMake и `build-local.sh`. Скрипт находит проект относительно собственного расположения, настраивает Release и принимает дополнительные параметры CMake. Зависимости должны быть установлены заранее. `DGS_BUILD_JOBS` по умолчанию равен 4. Для ручной настройки выполните `cmake -S build -B _/build`; `backend/CMakeLists.txt` определяет проект движка. Созданные файлы и `bin/dgs-server` находятся в `_/build/`, отдельно от скриптов сборки.

После компиляции установка для промышленной эксплуатации от имени root выполняется командой `cmake --install _/build --prefix /usr/local`. Правила подготовки веб-ресурсов расположены в `deploy/scripts/ui-assets.cmake`; `frontend/sources.cmake` перечисляет входные файлы, а `frontend/embed.py` генерирует встроенные C++-ресурсы. Главный README расположен в корне, региональные версии — в `doc/`.
