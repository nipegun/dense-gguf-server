Dense GGUF Server एक स्वतंत्र परियोजना है, जिसे **NiPeGun** विकसित और अनुरक्षित करते हैं।

DGS निम्न सघन मॉडल और उनसे संबंधित वेब चैट एप्लिकेशन प्रदान करता है:

- Qwen3.8-27B
- Qwen3.5-9B
- Qwen3.5-4B
- Qwen3.5-2B

GLM और Kimi के सभी संस्करणों सहित अन्य भाषा मॉडल समर्थित नहीं हैं। MoE मॉडल भी निषिद्ध हैं। सर्वर मूल GGUF पहचान और परतों के आयाम जाँचता है; अनुमानात्मक डिकोडिंग के ड्राफ़्ट मॉडल पर भी यही जाँच लागू है। अनुमत मॉडलों के क्वांटाइज़ेशन समर्थित रहते हैं।

## Debian पर बिल्ड और संचालन

Debian 13 या C++17, CMake 3.19+, Python 3.13+ और Node.js 20.19+ अथवा 22.12+ वाले संगत सिस्टम का उपयोग करें। पैकेज root के रूप में स्थापित करें:

```sh
apt-get update
apt-get install -y build-essential cmake ninja-build pkg-config libssl-dev python3 nodejs npm
cmake -S build -B _/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build _/build --target dgs-server -j 8
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --host 127.0.0.1 --port 8080
```

`http://127.0.0.1:8080` खोलें। मॉडल वेट अलग से देने होंगे। चित्र/वीडियो के लिए `--mmproj` से संबंधित Qwen प्रोजेक्टर चुनें; वीडियो प्रसंस्करण के लिए FFmpeg भी आवश्यक है। ऑडियो मॉडल और ऑडियो उत्पन्न करना समर्थित नहीं है।

Release मोड, नेटिव CPU कर्नेल और समर्थित लिंक-समय अनुकूलन डिफ़ॉल्ट रूप से सक्रिय हैं। CUDA और Vulkan बिल्ड के लिए संबंधित SDK के साथ `-DGGML_CUDA=ON` या `-DGGML_VULKAN=ON` उपयोग करें। लक्ष्य CPU के लिए बिल्ड करें या `-DGGML_NATIVE=OFF` चुनें। थ्रूपुट में किसी वृद्धि को मापा नहीं गया है।

## केवल वर्तमान प्रारूप

केवल GGUF v3 स्वीकार किया जाता है। `general.name`, अथवा `general.basename` और `general.size_label` का संयोजन, अनुमत मॉडल की पहचान करना चाहिए; केवल फ़ाइलनाम पर्याप्त नहीं है। यह मेटाडेटा और आयामों की नीति है, वेट की प्रामाणिकता का सत्यापन नहीं। आर्किटेक्चर के आयाम समान होने मात्र से Qwen3.5-27B को Qwen3.8-27B के रूप में स्वीकार नहीं किया जाता।

चैट के लिए मॉडल का पूरा Jinja टेम्पलेट या `--chat-template-file` आवश्यक है। पुराना स्थिर-टेम्पलेट इंजन, `--jinja`/`--no-jinja` स्विच, अप्रचलित C API, लंबे CLI विकल्पों की पुरानी वैकल्पिक वर्तनियाँ और पुराना तर्क मोड हटा दिए गए हैं। वर्तमान `/api/v1/*` API अनुबंध बने हुए हैं; पुराने उपनाम `/completion` और `/embedding` हट गए हैं।

वेब वर्तमान संग्रहण नेमस्पेस `DgsUi` और संरचित संदेश उपयोग करता है। पुराने नेमस्पेस, थीम, संदेश चिह्न और पुराने JSON वार्तालाप निर्यात पढ़े या माइग्रेट नहीं किए जाते। वर्तमान JSONL सत्र निर्यात और ZIP संग्रह समर्थित हैं। ब्राउज़र का पुराना डेटा नहीं मिटाया जाता। MCP में StreamableHTTP या WebSocket उपयोग होता है; पुराना SSE परिवहन और स्वचालित फ़ॉलबैक हटा दिए गए हैं। क्लिपबोर्ड के लिए सुरक्षित संदर्भ में वर्तमान Clipboard API चाहिए।

## संरचना और दस्तावेज़

- `backend/`: सर्वर, Qwen इन्फ़रेंस, साझा टेंसर कर्नेल और Qwen विज़न।
- `frontend/`: वर्तमान Svelte एप्लिकेशन और निश्चित संस्करण वाली निर्भरताएँ।
- `deploy/`: बिल्ड सहायक और स्थानीय वेब इंटरफ़ेस का समावेश।
- [तकनीकी मानचित्र](CODE.hi-IN.md) और [मैनुअल](MANUAL.hi-IN.md)।

सामान्य बिल्ड स्थानीय वेब को कंपाइल करके समाहित करता है। `cd frontend && npm ci && npm run build` से पहले से बनी वेब को दोबारा उपयोग करने के लिए `-DDGS_USE_LOCAL_UI=ON` सेट करें। स्रोत बदलने के बाद संसाधन फिर बनाएँ। `-DDGS_BUILD_UI=OFF` समाहित संसाधन छोड़ देता है; उस स्थिति में `--path` को वर्तमान बिल्ड किए गए वेब फ़ोल्डर के साथ उपयोग करें।

परियोजना के नियम परीक्षण निषिद्ध करते हैं। सत्यापन केवल कंपाइलेशन और स्थिर प्रकार-जाँच तक सीमित है; मॉडल इन्फ़रेंस या बेंचमार्क नहीं चलाए गए। परियोजना Git का उपयोग नहीं करती; संरक्षित `.git` फ़ोल्डर उसका स्वामी स्वयं हटाता है।

## दैनिक उपयोग

वेब में बातचीत शुरू करें, लोड हुआ अनुमत मॉडल चुनें और पाठ या समर्थित चित्र/वीडियो संलग्नक भेजें। सेटिंग्स सैंपलिंग, संदर्भ और टूल नियंत्रित करती हैं। `-c` संदर्भ लंबाई, `-t` CPU थ्रेड और `-ngl auto` स्वचालित GPU स्थान-निर्धारण तय करता है। प्रमाणीकरण के लिए `--api-key` उपयोग करें। संगत क्लाइंट `http://127.0.0.1:8080/api/v1` और `/api/v1/chat/completions` से जुड़ते हैं। मॉडल फ़ोल्डरों में अन्य फ़ाइलें हो सकती हैं, लेकिन लोडर असमर्थित चेकपॉइंट अस्वीकार करता है।

लोड विफल होने पर पहचान, आर्किटेक्चर, आयाम और GGUF संस्करण जाँचें; जाँच से बचने के लिए दूसरे मॉडल का लेबल न बदलें। मेमोरी कम हो तो संदर्भ, बैच आकार या GPU ऑफ़लोड मात्रा घटाएँ। वेब न मिले तो उसे फिर बिल्ड करें या `--path` दें।

## MCP और वेब सुविधाएँ

`--local-shell-mcp-server` या `DGS_ARG_LOCAL_SHELL_MCP_SERVER=1` से अंतर्निहित शेल MCP सर्वर चालू करें। वेब उसे स्वतः पहचानता है और टूल चलाने की अनुमति माँगता है। वह स्थापित Bash, Zsh, sh और PowerShell उपलब्ध कराता है, कमांड, stdout और stderr दिखाता है और हर कॉल JSONL में दर्ज करता है।

वेब में CPU/GPU तथा मेमोरी मॉनिटर, स्थिति पट्टी, सर्वर पर साझा सेटिंग्स, 15 इंटरफ़ेस भाषाएँ, चुनी गई क्षेत्रीय भाषा में उत्तर देने का वैकल्पिक निर्देश और वेब तथा अन्य API क्लाइंट की कतार सूचनाएँ हैं। मॉडल देखना, डाउनलोड करना, वार्तालाप टैब और सघन मॉडल नीति बनी रहती हैं।

वेब `/` पर और API डिफ़ॉल्ट रूप से `/api` के अंतर्गत है। OpenAI-संगत क्लाइंट को `/api/v1` आधार पथ रखना चाहिए। Swagger दस्तावेज़ `/api/doc/` पर हैं। नए API पथों के रूट उपनाम नहीं हैं। `--api-prefix` से `/api` के अंतर्गत पथ चुना जा सकता है; `/api/config.js` उसे वेब तक पहुँचाता है।

## स्थानीय शेल MCP

```sh
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --local-shell-mcp-server --api-key YOUR_KEY
```

वेब खोलकर API कुंजी दर्ज करें। सर्वर पर सक्रिय होने पर `local shell mcp server` स्वतः दिखता है; इसे सभी वार्तालापों या किसी एक के लिए बंद किया जा सकता है। `bash.run`, `zsh.run`, `sh.run` और `psh.run` केवल स्थापित इंटरप्रेटर के लिए उपलब्ध हैं। एंडपॉइंट `POST /api/mcp/shell` है; MCP Streamable HTTP, JSON उत्तर और `2025-11-25` प्रोटोकॉल संस्करण उपयोग होता है।

हर टूल `command`, वैकल्पिक `cwd` और सेकंड में वैकल्पिक `timeout` स्वीकार करता है: डिफ़ॉल्ट 60, अधिकतम 3600। कॉल बिना इंटरैक्टिव टर्मिनल के स्वतंत्र प्रक्रियाओं में चलती हैं। कार्य फ़ोल्डर और वातावरण के बदलाव अगली कॉल में नहीं जाते। रद्द करने या समय समाप्त होने पर प्रक्रिया समूह बंद होता है। कमांड सर्वर खाते की अनुमतियों से चलती हैं; API कुंजी से प्रवेश सुरक्षित करें।

चैट में stdin (कमांड), stdout, stderr और निकास कोड अलग दिखते हैं। प्रदर्शन सेटिंग्स इन्हें अपने आप खोल सकती हैं। `~/.dgs/local-shell-mcp-server/` के लॉग पूरा कमांड और आउटपुट रखते हैं, हर कॉल के लिए समय-चिह्न वाला JSONL। चैट लंबे आउटपुट को छोटा कर सकती है। फ़ाइलें केवल सर्वर खाते के लिए हैं और स्वतः रोटेट नहीं होतीं।

जिन Linux मशीनों पर sudo पहले से है, वहाँ पासवर्ड अनुरोध सक्रिय इनपुट वाले स्वीकार/रद्द संवाद में दिखते हैं। पासवर्ड केवल सहायक प्रक्रिया को भेजा जाता है, मॉडल, बातचीत या लॉग को नहीं। उपयोगकर्ता के उत्तर की प्रतीक्षा में कमांड की समय-सीमा रुकती है; पाँच मिनट तक उत्तर न मिलने पर अनुरोध समाप्त होता है। परियोजना sudo स्थापित नहीं करती और उत्पादन संचालन में इसकी आवश्यकता नहीं है।

## निगरानी और साझा प्राथमिकताएँ

साइडबार में **निगरानी** खोलें या नीचे की स्थिति पट्टी दबाएँ। पृष्ठ दिखते समय CPU/GPU उपयोग हर दो सेकंड में बदलता है। पूरा दृश्य ड्राइवर द्वारा उपलब्ध RAM, VRAM, तापमान और बिजली उपयोग भी दिखाता है। मेमोरी में सघन वेट, MTP/ड्राफ़्ट वेट, KV/पुनरावर्ती कैश, गणना बफ़र, सहेजे प्रॉम्प्ट/चेकपॉइंट, अन्य उपयोग और खाली स्थान अलग हैं। NVIDIA के लिए NVML गतिशील रूप से और AMD के लिए sysfs उपयोग होता है; अनुपलब्ध माप अज्ञात रहते हैं। राउटर मोड लोड हुई सहायक प्रक्रियाओं का योग करता है, बिना मॉडल लोड किए या जगाए।

सेटिंग्स सर्वर खाते की `~/.dgs/config/ui-settings.json` फ़ाइल में 0600 अनुमतियों के साथ रहती हैं। एक सर्वर के सभी ब्राउज़र कॉन्फ़िगरेशन, थीम, भाषा, पसंदीदा मॉडल और टूल प्राथमिकताएँ साझा करते हैं। सहेजने से पूरा दस्तावेज़ बदलता है; साथ में बदलाव होने पर अंतिम सफल सेव मान्य होता है। API कुंजियाँ, बातचीत और अस्थायी नेविगेशन/स्ट्रीम स्थिति ब्राउज़र में रहती हैं। पुरानी ब्राउज़र सेटिंग्स माइग्रेट नहीं होतीं।

सामान्य सेटिंग्स में भाषा चुनें। बदलाव चयन सहेजकर इंटरफ़ेस फिर लोड करता है; पहले अन्य लंबित बदलाव सहेजें। समर्थित स्थानीय रूप `de-DE`, `en-GB`, `en-US`, `es-AR`, `es-ES`, `fr-FR`, `he-IL`, `hi-IN`, `it-IT`, `ja-JP`, `ko-KR`, `pt-BR`, `pt-PT`, `ru-RU` और `zh-CN` हैं। अमेरिकी अंग्रेज़ी डिफ़ॉल्ट है और अनुपलब्ध अनुवादों का विकल्प भी। **इंटरफ़ेस की भाषा में उत्तर दें** (Respond in the interface language) सक्रिय करने से नए चैट अनुरोधों, टूल चक्रों, शीर्षकों और KV पूर्व-भरण में क्षेत्रीय निर्देश जुड़ता है। पुराने संदेश अनुवादित नहीं होते; पालन मॉडल पर निर्भर है।

स्लॉट की प्रतीक्षा कर रहे अनुरोध की स्थिति बताती है कि उससे आगे कितने अनुरोध हैं और क्या कोई सीधे API से आया है। सामान्य API क्लाइंट का उत्तर प्रारूप नहीं बदलता। केवल `"dgs_client": "webui"` चिह्नित स्ट्रीमिंग अनुरोधों को `dgs_queue` घटनाएँ मिलती हैं।

फ़्रंटएंड विकास में `npm run dev`, `/api` को `http://localhost:9931` तक प्रॉक्सी करता है; अन्य सर्वर के लिए `VITE_PUBLIC_SERVER_ORIGIN` सेट करें। उत्पादन बिल्ड वेब और स्थानीय Swagger को समाहित करता है, इसलिए बाहरी दस्तावेज़ CDN आवश्यक नहीं है।

## स्रोत और बिल्ड फ़ोल्डर

`build/` में CMake प्रवेश बिंदु और `build-local.sh` हैं। स्क्रिप्ट अपनी स्थिति के आधार पर परियोजना खोजती है, Release सेट करती है और अतिरिक्त CMake विकल्प लेती है। निर्भरताएँ पहले स्थापित होनी चाहिए। `DGS_BUILD_JOBS` का डिफ़ॉल्ट 4 है। हाथ से कॉन्फ़िगर करने के लिए `cmake -S build -B _/build` चलाएँ; `backend/CMakeLists.txt` इंजन परियोजना है। बनी हुई फ़ाइलें और `bin/dgs-server`, `_/build/` में बिल्ड स्क्रिप्ट से अलग रहते हैं।

कंपाइल करने के बाद root के रूप में उत्पादन स्थापना के लिए `cmake --install _/build --prefix /usr/local` चलाएँ। वेब तैयार करने के CMake नियम `deploy/scripts/ui-assets.cmake` में हैं; `frontend/sources.cmake` इनपुट सूची देता है और `frontend/embed.py` समाहित C++ संसाधन बनाता है। मुख्य README रूट में और क्षेत्रीय संस्करण `doc/` में हैं।
