# מדריך DGS

[de-DE](MANUAL.de-DE.md) · [en-GB](MANUAL.en-GB.md) · [en-US](MANUAL.md) · [es-AR](MANUAL.es-AR.md) · [es-ES](MANUAL.es-ES.md) · [fr-FR](MANUAL.fr-FR.md) · **he-IL** · [hi-IN](MANUAL.hi-IN.md) · [it-IT](MANUAL.it-IT.md) · [ja-JP](MANUAL.ja-JP.md) · [ko-KR](MANUAL.ko-KR.md) · [pt-BR](MANUAL.pt-BR.md) · [pt-PT](MANUAL.pt-PT.md) · [ru-RU](MANUAL.ru-RU.md) · [zh-CN](MANUAL.zh-CN.md)

Dense GGUF Server הוא פרויקט עצמאי שמפותח ומתוחזק בידי **NiPeGun**.

DGS מספק שירות למודלים הצפופים הבאים וליישום הצ'אט הנלווה:

- Qwen3.8-27B
- Qwen3.5-9B
- Qwen3.5-4B
- Qwen3.5-2B

מודלי שפה אחרים אינם נתמכים, ובכללם כל הגרסאות של GLM ושל Kimi. מודלי MoE נותרים מחוץ לתחום. השרת בודק את הזהות המקורית ב־GGUF ואת ממדי השכבות, גם בטעינת מודל טיוטה לפענוח ספקולטיבי. גרסאות הקוונטיזציה של המודלים המותרים נתמכות.

<a id="local-build"></a>

## בנייה והפעלה ב־Debian

השתמשו ב־Debian 13 או במערכת תואמת עם C++17,‏ CMake 3.19+,‏ Python 3.13+ ו־Node.js 20.19+ או 22.12+. התקינו את החבילות בתור root:

<div dir="ltr">

```sh
apt-get update
apt-get install -y build-essential cmake ninja-build pkg-config libssl-dev python3 nodejs npm
cmake -S build -B _/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build _/build --target dgs-server -j 8
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --host 127.0.0.1 --port 8080
```

</div>

פתחו את `http://127.0.0.1:8080`. המשקלים ניתנים בנפרד. לתמונות ולווידאו יש לציין מקרן Qwen מתאים באמצעות `--mmproj`; עיבוד וידאו דורש גם FFmpeg. מודלי שמע ויצירת שמע אינם נתמכים.

מצב Release, גרעיני CPU מותאמים למחשב ואופטימיזציה בזמן הקישור, כאשר היא נתמכת, מופעלים כברירת מחדל. בניית CUDA או Vulkan משתמשת ב־`-DGGML_CUDA=ON` או ב־`-DGGML_VULKAN=ON` יחד עם ה־SDK המתאים. בנו עבור המעבד של מערכת היעד או השתמשו ב־`-DGGML_NATIVE=OFF`. לא נמדד שיפור בתפוקה.

## פורמטים עדכניים בלבד

רק GGUF v3 מתקבל. השדה `general.name`, או הצירוף של `general.basename` עם `general.size_label`, חייב לזהות מודל מותר; שם הקובץ אינו מספיק. זוהי בדיקת מטא־נתונים וממדים, לא אימות המקוריות של המשקלים. קובץ Qwen3.5-27B אינו מתקבל בתור Qwen3.8-27B רק משום שממדי הארכיטקטורות זהים.

הצ'אט דורש תבנית Jinja מלאה של המודל או `--chat-template-file`. מנוע התבניות הקבועות הישן, המתג `--jinja`/`--no-jinja`, ממשקי C מיושנים, כתיבים ישנים של אפשרויות CLI ארוכות ומצב ההסקה הישן הוסרו. חוזי ה־API העדכניים תחת `/api/v1/*` נשמרים; הכינויים הישנים `/completion` ו־`/embedding` הוסרו.

הממשק משתמש במרחב האחסון העדכני `DgsUi` ובהודעות מובנות. הוא אינו קורא או ממיר מרחבי אחסון, ערכות נושא, סימוני הודעות או ייצוא JSON ישנים. ייצוא מפגשים עדכני ב־JSONL וארכיוני ZIP נתמכים. נתונים ישנים בדפדפן אינם נמחקים. MCP משתמש ב־StreamableHTTP או ב־WebSocket; תעבורת SSE הישנה והמעבר האוטומטי אליה הוסרו. פעולות הלוח דורשות את Clipboard API העדכני בהקשר מאובטח.

## מבנה ותיעוד

- `backend/`: שרת, הסקת Qwen, גרעיני טנזורים משותפים וראייה של Qwen.
- `frontend/`: יישום Svelte העדכני והתלויות שלו בגרסאות קבועות.
- `deploy/`: עזרי בנייה והטמעת הממשק המקומי.
- [מפה טכנית](CODE.he-IL.md) ו[מדריך שימוש](MANUAL.he-IL.md).

הבנייה הרגילה בונה ומטמיעה את הממשק המקומי. לשימוש חוזר בממשק שכבר נבנה עם `cd frontend && npm ci && npm run build`, הגדירו `-DDGS_USE_LOCAL_UI=ON`. לאחר שינוי המקורות יש לבנות את המשאבים מחדש. האפשרות `-DDGS_BUILD_UI=OFF` משמיטה משאבים מוטמעים; במצב זה השתמשו ב־`--path` עם תיקיית ממשק עדכנית שכבר נבנתה.

כללי הפרויקט אוסרים בדיקות. האימות מוגבל להידור ולניתוח טיפוסים סטטי; לא הורצו הסקת מודלים או מבחני ביצועים. הפרויקט אינו משתמש ב־Git; בעליו מסיר ידנית את התיקייה המוגנת `.git`.

## שימוש יום־יומי

פתחו שיחה בממשק, בחרו מודל מותר שכבר נטען ושלחו טקסט או תמונות/וידאו נתמכים. ההגדרות שולטות בדגימה, בהקשר ובכלים. האפשרות `-c` קובעת את אורך ההקשר, `-t` את תהליכוני ה־CPU ו־`-ngl auto` את ההצבה האוטומטית ב־GPU. השתמשו ב־`--api-key` לצורך אימות. לקוחות תואמים מתחברים ל־`http://127.0.0.1:8080/api/v1` ול־`/api/v1/chat/completions`. תיקיות המודלים יכולות להכיל קבצים נוספים, אך הטוען דוחה נקודות ביקורת שאינן נתמכות.

אם הטעינה נכשלת, בדקו את הזהות, הארכיטקטורה, הממדים וגרסת GGUF. אין לשנות את תוויותיו של מודל אחר כדי לעקוף את הבדיקה. אם חסר זיכרון, הקטינו את ההקשר, גודל האצווה או היקף ההעברה ל־GPU. אם הממשק חסר, בנו אותו מחדש או הגדירו `--path`.

## MCP ויכולות הממשק

הפעילו את שרת ה־MCP המובנה למעטפות באמצעות `--local-shell-mcp-server` או `DGS_ARG_LOCAL_SHELL_MCP_SERVER=1`. הממשק מזהה אותו אוטומטית ומבקש הרשאה להפעלת כלים. הוא מציע את Bash,‏ Zsh,‏ sh ו־PowerShell המותקנים, מציג פקודה, stdout ו־stderr, ומתעד כל קריאה ב־JSONL.

הממשק כולל ניטור CPU/GPU וזיכרון, שורת מצב, הגדרות משותפות בשרת, בחירה בין 15 שפות, הוראה אופציונלית להשיב בשפה האזורית שנבחרה, והודעות תור המבדילות בין בקשות הממשק ובין לקוחות API אחרים. עיון במודלים, הורדות, לשוניות שיחה ומדיניות המודלים הצפופים נשמרים.

הממשק מוגש ב־`/`, וה־API נמצא כברירת מחדל תחת `/api`. לקוחות התואמים ל־OpenAI חייבים להשתמש ב־`/api/v1` כנתיב בסיס. תיעוד Swagger זמין ב־`/api/doc/`. לנתיבי ה־API החדשים אין כינויים ברמת השורש. האפשרות `--api-prefix` מאפשרת נתיב תחת `/api`, ו־`/api/config.js` מפרסם אותו לממשק.

## MCP למעטפות מקומיות

<div dir="ltr">

```sh
./_/build/bin/dgs-server -m /path/to/Qwen3.5-4B.gguf --local-shell-mcp-server --api-key YOUR_KEY
```

</div>

פתחו את הממשק והזינו את מפתח ה־API. הרשומה `local shell mcp server` מופיעה אוטומטית כשהשרת מפעיל אותה, וניתן להשביתה באופן כללי או לכל שיחה. הכלים `bash.run`, `zsh.run`, `sh.run` ו־`psh.run` מוצעים רק למפרשים שהותקנו. נקודת הקצה היא `POST /api/mcp/shell`, עם MCP Streamable HTTP, תשובות JSON וגרסת פרוטוקול `2025-11-25`.

כל כלי מקבל `command`, וכן `cwd` ו־`timeout` אופציונליים. הזמן הוא בשניות: ברירת המחדל 60 והמקסימום 3600. הקריאות מופעלות בתהליכים עצמאיים ללא מסוף אינטראקטיבי. שינויי תיקיית העבודה והסביבה אינם עוברים בין קריאות. ביטול או חריגה מהזמן מסיימים את קבוצת התהליכים. הפקודות רצות בהרשאות חשבון השרת; הגנו על הגישה במפתח API.

הצ'אט מציג בנפרד stdin (הפקודה), stdout ו־stderr עם קוד היציאה. הגדרות התצוגה מאפשרות להרחיב את התיבות אוטומטית. היומנים תחת `~/.dgs/local-shell-mcp-server/` שומרים את מלוא הפקודה והפלט בקובץ JSONL מתוארך לכל קריאה; פלט ארוך עשוי להתקצר בצ'אט. הקבצים פרטיים לחשבון השרת ולא מתחלפים אוטומטית.

במערכות Linux שכבר מותקן בהן sudo, בקשות הסיסמה מוצגות בדו־שיח עם מיקוד בשדה הקלט וכפתורי אישור/ביטול. הסיסמה נשלחת רק לתהליך העזר, לא למודל, לשיחה או ליומנים. ההמתנה למשתמש עוצרת את ספירת הזמן של הפקודה; בקשה שלא נענתה פגה לאחר חמש דקות. הפרויקט אינו מתקין sudo והפעלתו בייצור אינה דורשת אותו.

## ניטור והעדפות משותפות

בחרו **ניטור** בסרגל הצד או לחצו על שורת המצב התחתונה. השימוש ב־CPU וב־GPU מתעדכן כל שתי שניות כשהדף מוצג. התצוגה המלאה מוסיפה RAM,‏ VRAM, טמפרטורה וצריכת חשמל כאשר מנהל ההתקן מספק אותם. הזיכרון מחולק למשקלים צפופים, משקלי MTP/טיוטה, מטמוני KV/מצב רקורנטי, מאגרי חישוב, פרומפטים/נקודות ביקורת שמורים, שימוש אחר וזיכרון פנוי. NVIDIA נקרא דינמית באמצעות NVML ו־AMD באמצעות sysfs; נתונים חסרים נשארים לא ידועים. מצב הנתב מסכם תהליכים שכבר נטענו בלי לטעון או להעיר מודלים.

ההגדרות נשמרות ב־`~/.dgs/config/ui-settings.json` של חשבון השרת בהרשאות 0600. כל הדפדפנים הפונים לאותו שרת משתפים תצורה, ערכת נושא, שפה, מועדפים והעדפות כלים. שמירה מחליפה את המסמך כולו; בעריכות בו־זמניות השמירה המוצלחת האחרונה קובעת. מפתחות API, שיחות ומצב זמני של ניווט וזרמים נשארים בדפדפן. הגדרות ישנות אינן מועברות.

בחרו שפה בהגדרות הכלליות. השינוי שומר את הבחירה וטוען את הממשק מחדש, ולכן יש לשמור קודם שינויים אחרים. האזורים והשפות הנתמכים הם `de-DE`, `en-GB`, `en-US`, `es-AR`, `es-ES`, `fr-FR`, `he-IL`, `hi-IN`, `it-IT`, `ja-JP`, `ko-KR`, `pt-BR`, `pt-PT`, `ru-RU`, `zh-CN`. אנגלית אמריקאית היא ברירת המחדל והחלופה לטקסט שלא תורגם. הפעילו **השב בשפת הממשק** (Respond in the interface language) כדי להוסיף הוראה אזורית לבקשות חדשות, סבבי כלים, כותרות ומילוי KV מראש. הודעות קיימות אינן מתורגמות; הציות תלוי במודל.

כאשר בקשת הסקה ממתינה לחריץ פנוי, מוצג מספר הבקשות שלפניה והאם חלקן הגיע ישירות מה־API. לקוחות API רגילים שומרים על פורמט התשובה שלהם. רק בקשות זרימה המסומנות ב־`"dgs_client": "webui"` מקבלות אירועי `dgs_queue`.

בפיתוח צד הדפדפן, `npm run dev` מנתב את `/api` אל `http://localhost:9931`; הגדירו `VITE_PUBLIC_SERVER_ORIGIN` כדי להשתמש בשרת אחר. בניית הייצור מטמיעה את הממשק ואת Swagger המקומי ואינה זקוקה ל־CDN חיצוני לתיעוד.

## תיקיות המקור והבנייה

`build/` מכילה את נקודת הכניסה של CMake ואת `build-local.sh`. הסקריפט מאתר את הפרויקט ביחס למיקומו, מגדיר בניית Release ומקבל אפשרויות CMake נוספות. התלויות חייבות להיות מותקנות מראש. ברירת המחדל של `DGS_BUILD_JOBS` היא 4. להגדרה ידנית הריצו `cmake -S build -B _/build`; פרויקט המנוע מוגדר ב־`backend/CMakeLists.txt`. הקבצים שנוצרים ו־`bin/dgs-server` נמצאים ב־`_/build/`, בנפרד מסקריפטי הבנייה.

אחרי ההידור, התקנה לייצור בתור root משתמשת ב־`cmake --install _/build --prefix /usr/local`. כללי CMake להכנת הממשק נמצאים ב־`deploy/scripts/ui-assets.cmake`, הקלטים מופיעים ב־`frontend/sources.cmake` ו־`frontend/embed.py` יוצר את משאבי ה־C++ המוטמעים. README הראשי נמצא בשורש והגרסאות האזוריות ב־`doc/`.
